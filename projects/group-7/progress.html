1 Set up the harness done

  • Spec written from the brief: five cases, three tools, rule codes, our choices for partly-valid and unclear requests.

2 Build the backend and the frontend done

files: src/domain/budget.js, src/service.js, src/server.js, public/index.html, data.json
  • One domain module holds the rule. A new proposal must fit spent + pending + cost ≤ cap; Approve re-checks spent + amount ≤ cap.
  • REST API: state, vendors, check, propose, approve, reject, demo reset. Refusals return HTTP 422 with BUDGET_CAP_EXCEEDED. No route changes the cap.
  • UI: budget meter, vendor list with a live check as you type, proposals with Approve/Reject, saved expenses. Only the Approve button saves.
