7. Add guardrails Done · Milestone 3 complete

2026-10-18
  • The core guard is unchanged: domain/rules.py refuses more than 3 hours for every client.
  • Case 5 is blocked from every client:
    • API: tested, MAX_DURATION_EXCEEDED.
    • MCP: tested, and live through Gemini CLI with approved=true.
    • Chat agent: tested with a model that falls for the note; it can't even propose the booking. Also covered by the live eval.
    • UI: tested.
  • Added layers (backend/app/guardrails.py):
    • Notes that read like instructions are flagged suspicious_note in every client. The UI shows them crossed out as "Ignored note".
    • Room data is labelled untrusted before the model sees it.
    • Purposes or names that read like instructions are refused on save with SUSPICIOUS_CONTENT, so no new injections get into data.json.
    • A reply that falsely claims "booked" or "confirmed" is corrected.
    • Every refused booking is written to backend/logs/audit.jsonl with its client.
  • Tests: 88 backend and 19 frontend tests pass. They run on a fixed seed, so new bookings in data.json don't change test results.
