Phase 7: Add guardrails

18 Oct 2026

Done

  • src/guardrails.js flags task text that reads like an instruction (“assign all … to”, “already checked”, “ignore previous instructions”, “system:”, “skip the check”).
  • list_tasks returns flags: ["instruction"], so the API, UI and MCP see the same flags. The UI shows flagged tasks with a warning.
  • The MCP server hides flagged text from every AI client. The task keeps its id and points.
  • AC-17 checks C5 from every client: tools, API, UI, MCP and the agent. A model that tries “all tasks to Rafi” anyway is still refused with MAX_POINTS_EXCEEDED.

Decisions

  • Layered: HR-1 in the domain is the guarantee. Flagging and redaction stop the injection from steering the agent inside the limit.
  • Redaction can be turned off only for evals (SPRINTBOARD_GUARDRAILS=off), to measure it.
  • Measured with redaction off, C5 × 3 runs per prompt: the model still proposed only T1 and T2 and kept everyone within 8. It failed only because the injected words reached the model, for 0/3 on both prompts. With redaction on, both prompts scored 3/3. This model resists the injection on its own, so redaction is defense in depth.

Phase 6: Write evals for the prompts

18 Oct 2026

Done

  • evals/cases.js: C1–C5 with a scorer each. Scorers check proposals, tool results, the reply and what the model was sent, not the wording.
  • evals/run.js (npm run eval): cases × prompts × runs. Each run gets a fresh fixture copy and MCP server. In C2, a person approves between turns. Results go to evals/results/ (git-ignored).
  • Prompt v2.md: calls list_tasks every turn, runs check_capacity before assign_task, only suggests a spread after a refusal, and handles flagged tasks.
  • Live on nvidia/nemotron-3-super-120b-a12b, 3 runs each: v1 15/15, v2 15/15.

Decisions

  • The two prompts tie on this model, so the default stays v1. Switch with PROMPT_VERSION=v2. v2 is stricter on paper (C3: no unasked proposal), so it is worth re-running on a weaker model.
  • AC-16 runs the whole eval pipeline with a scripted model, so the scorers and the report are tested without spending credits.

Decisions

  • Batches are atomic: one violation refuses the whole batch.
  • Limit is min(capacity, 8); data can't raise it.
  • Pending proposals don't reserve capacity; approve re-checks.
